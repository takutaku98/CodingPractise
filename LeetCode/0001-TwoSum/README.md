# 1. Two Sum

## 問題

配列 `nums` の中から、足すと `target` になる 2 つの要素を見つけて、そのインデックスを返す。

- 例: `nums = [2, 7, 11, 15]`, `target = 9` → 答えは `[0, 1]`(`2 + 7 = 9`)

## 解法: ハッシュマップによる一発走査(one-pass)

### 素朴な解法との比較

一番単純なのは全ペアを二重ループで総当たりする方法で、要素数 n に対して **O(n²)**。
この解法は「過去に見た数字を記録しておく」ことでループ 1 回・**O(n)** で解く(代わりに辞書のぶん空間 O(n) を使う)。

### 核心となる発想

> `nums[i] + x = target` となる相棒 `x` は、`x = target - nums[i]` と計算で求められる。

この相棒をコード内では `complement`(補数)と呼ぶ。
そして Dictionary に「**今まで見た値 → そのインデックス**」を記録しながら進む。

### 各要素での処理

1. **相棒を計算する** — 自分と足して target になる値は `target - nums[i]`
2. **相棒がすでに辞書にいるか調べる** — いれば、相棒のインデックスと今のインデックスがペアなので即リターン
3. **いなければ自分を登録する** — 「値 `nums[i]` はインデックス `i` にいた」と記録し、後から来る要素が自分を相棒として見つけられるようにする

### 具体例のトレース

`nums = [2, 7, 11, 15]`, `target = 9` の場合:

| i | nums[i] | complement (9 - nums[i]) | 辞書の中身 | 動き |
|---|---------|--------------------------|------------|------|
| 0 | 2 | 7 | (空) | 7 はまだいない → `{2: 0}` を登録 |
| 1 | 7 | 2 | `{2: 0}` | **2 がいる!** → `[0, 1]` を返す |

## ポイント

- **`TryGetValue` は平均 O(1)** なので全体で O(n)。総当たりの O(n²) より圧倒的に速い
- **「探してから登録する」順番が重要**。先に登録すると、`target = 6`, `nums[0] = 3` のように自分自身をペアにしてしまう事故が起きる。探す時点では自分はまだ辞書にいないので、この順番なら安全
- `TryGetValue(complement, out var index1)` は「キーがあれば true を返しつつ値を `index1` に取り出す」を 1 回の検索で済ませる C# のイディオム
- 先頭の `if (nums == null)` と最後の `return [-1, -1]` は null 入力・答えなしの保険(LeetCode の本来の問題では答えが必ず存在する前提なので、実際にはほぼ到達しない)

## 余談: `++i` と `i++`

for ループの `++i` は `i++` と書いても動作・性能とも完全に同じ(式の値を誰も使っていないため)。

- 違いは「式としての値」だけ: `i++` はインクリメント**前**の値、`++i` はインクリメント**後**の値を返す
- C++ ではクラス型イテレータに対して後置 `i++` が余分なコピーを生むため「値を使わないなら前置」が作法とされ、その習慣を持ち込む人がいる
- C# の `int` ではコンパイラがどちらも同じコードに最適化するので差はゼロ。C# では `i++` が多数派

```csharp
var i = 5;
var a = i++;  // a = 5, i = 6(古い値を返してから増える)

var j = 5;
var b = ++j;  // b = 6, j = 6(増えてから新しい値を返す)
```

## 計算量

- 時間: O(n)
- 空間: O(n)
